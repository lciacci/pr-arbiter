phase 2 — code generation from spec (writer-loop)

Phase 2 ports the reviewer + arbiter architecture from PR review to a writer-loop: a writer agent produces code, reviewer + arbiter critique, writer revises. Across 13 tasks (197 tests), both arms converge at the same rate (11/13), but the failure mix shifts: multi-agent fixes a stuck correctness bug (task_007) and regresses on an underspec ambiguity (task_013). Same tradeoff as Phase 1: helps with correctness, hurts on ambiguity.

Executive summary

Three agents, in order: a single-pass reviewer that surfaces issues adversarially; an independent arbiter that does a second-pass review focused on what the reviewer missed (especially correctness-critical and architectural issues); and a mutual-triage step where two voices independently vote KEEP/DROP/UNSURE on the merged finding list. Agreement on KEEP → blocking finding; agreement on DROP → dropped; disagreement → advisory.

Four iterations, each an architectural change rather than a prompt nudge. Iter1 added severity anchoring to the reviewer (big precision win). Iter2 changed the arbiter from a triage filter to an independent reviewer (the critical-catching move). Iter3 added mutual triage to split the merged output into blocking vs advisory tiers (precision recovery without losing the critical). Iter4 was a corpus discovery: the durable pr_007 "false positive" turned out to be the reviewer correctly flagging a real bug the rubric mislabeled.

All measurement against the same 20-PR Flask 3.0.0 corpus, 55 expected findings across 4 severity tiers. Eval-first throughout — no prompt iteration without re-running the full corpus.

Architecture (iter3)

Worked example: pr_009

pr_009 introduces a sanitize_user_html helper using regex substitution to strip <script> tags and on* handler attributes. Looks reasonable on a quick read. 

def sanitize_user_html(raw: str) -> str:
    """Sanitize a user-supplied HTML string for safe rendering."""
    import re
    cleaned = re.sub(r"<script.*?>.*?</script>", "", raw,
                     flags=re.IGNORECASE | re.DOTALL)
    cleaned = re.sub(r'\s+on\w+\s*=\s*"[^"]*"', "", cleaned,
                     flags=re.IGNORECASE)
    return cleaned

Regex-based HTML sanitization is a well-known anti-pattern. <scr<script>ipt> survives one pass. Single-quoted handlers (onclick='alert(1)') survive. Many vectors (iframe, svg, object, data URIs) are entirely unhandled. Output goes to a Jinja |safe filter — stored XSS class.

  • Single-agent reviewer: empty review. Caught nothing.
  • Independent arbiter (iter2): 5 findings, 3 critical.
  • Mutual triage (iter3): all 3 criticals voted KEEP by both voices → blocking tier.

Full step-by-step in results/pr_009_worked_example.md.

Phase 2 — writer-loop (code generation from spec)

Phase 2 tests whether the Phase 1 reviewer + arbiter architecture generalizes to a writer-loop: a writer agent produces code from a spec; reviewer + arbiter critique the attempt; writer revises; loop until tests pass or budget runs out. Corpus is 13 deterministic tasks (197 tests) across four difficulty tiers — easy, medium, hard, and a deliberately underspec tier where the spec is ambiguous and the tests pick a specific interpretation.

Critical design choices, locked before the API spend:

  • Writer never sees the tests. Spec only. Showing tests would collapse the task to "fit-the-tests" and erase the multi-agent surface.
  • Writer never sees test failures. Only a binary 5/17 passing-style signal. Tracebacks would leak ground truth.
  • Reviewer sees attempt history. Catches regression / oscillation. Arbiter sees latest only — preserves the anti-anchoring independence property from Phase 1.
  • Budget = 3 iterations. 1-iter convergence is one-shot (no multi-agent value). Past 5 is stuck.
  • Same model (Sonnet 4.6) for all agents — the ablation argument is preserved.

Worked examples — where the signal lives

task_007 — multi-agent WIN

JSON path resolver (medium). Writer's first attempt had multiple correctness bugs: bracket parsing, mutable sentinel default, dot-handling on edge cases, swallowed exceptions.

  • writer-alone: 15/17 → 16/17 → 16/17. Stuck across 3 iterations. Binary signal said "wrong" but not where.
  • multi-agent: iter1 timed out (infinite loop). Reviewer + arbiter together produced 10 specific findings — bracket parser, sentinel default, dot-handling, swallowed exceptions. iter2: 17/17.

Direct analog of the Phase 1 pr_009 result: multi-agent provides the diagnostic detail the binary signal can't.

task_013 — multi-agent LOSS

Whitespace normalizer (underspec). Spec is ambiguous on whether spaces adjacent to newlines should be stripped or preserved.

  • writer-alone: 16/17 → 12/17 → 17/17. Oscillated, recovered.
  • multi-agent: 11/17 → 16/17 → 13/17. Arbiter confidently asserted "spaces adjacent to newlines should be stripped." Writer obeyed. Tests required preserving them.

Critic certainty on an ambiguous spec pushes the writer in the wrong direction. Mirror of the Phase 1 iter1 arbiter overshoot — same failure mode, different surface.

What this means

Two phases, two corpora, two surfaces (review vs write), same architectural finding:

  • Independent multi-agent review beats single-agent on correctness bugs the latter can't catch alone.
  • Independent multi-agent review loses to single-agent on ambiguity where the critic introduces false certainty.
  • The tradeoff is real, not a Phase 1 artifact.

Phase 2 has no mutual-triage analog yet. The Phase 1 fix for overshoot (two voices voting KEEP/DROP) doesn't map cleanly — feedback flows to the writer as a stream, not a discrete list. Whether some analog (e.g. critic confidence tagging, dual-voice gating of spec-interpretation feedback) closes the underspec gap is the load-bearing question for iter 2.

Methodology notes

  • Eval-first. No prompt change without rerunning the full 20-PR corpus.
  • Critical recall reported separately. Weighted-average score would have hidden the iter1 arbiter dropping criticals to gain medium-tier precision.
  • Per-stage capture. Runner saves reviewer-only and arbiter-only finding lists per PR. Inspecting the divergence is what revealed both multi-agent value and the iter4 corpus mislabel.
  • Cache-reuse across iterations. Iter2 reviewer findings get reused as iter3 input — no re-running the upstream agent when only the downstream change matters.
