pr-arbiter

A reviewer + arbiter multi-agent system for code review. Phase 1 POC.

7 / 8
critical bugs caught — multi-agent vs 6/8 single-agent

The multi-agent pipeline (reviewer + independent arbiter + mutual triage) catches a critical security bug — regex-based HTML sanitization on pr_009 — that the best single-agent reviewer misses across every prompt variant tried. Comparable precision, fewer false positives, two-tier output (blocking + advisory) that matches how senior reviewers actually work.

Executive summary

Three agents, in order: a single-pass reviewer that surfaces issues adversarially; an independent arbiter that does a second-pass review focused on what the reviewer missed (especially correctness-critical and architectural issues); and a mutual-triage step where two voices independently vote KEEP/DROP/UNSURE on the merged finding list. Agreement on KEEP → blocking finding; agreement on DROP → dropped; disagreement → advisory.

Four iterations, each an architectural change rather than a prompt nudge. Iter1 added severity anchoring to the reviewer (big precision win). Iter2 changed the arbiter from a triage filter to an independent reviewer (the critical-catching move). Iter3 added mutual triage to split the merged output into blocking vs advisory tiers (precision recovery without losing the critical). Iter4 was a corpus discovery: the durable pr_007 "false positive" turned out to be the reviewer correctly flagging a real bug the rubric mislabeled.

All measurement against the same 20-PR Flask 3.0.0 corpus, 55 expected findings across 4 severity tiers. Eval-first throughout — no prompt iteration without re-running the full corpus.

Architecture (iter3)

Worked example: pr_009

pr_009 introduces a sanitize_user_html helper using regex substitution to strip <script> tags and on* handler attributes. Looks reasonable on a quick read. 

def sanitize_user_html(raw: str) -> str:
    """Sanitize a user-supplied HTML string for safe rendering."""
    import re
    cleaned = re.sub(r"<script.*?>.*?</script>", "", raw,
                     flags=re.IGNORECASE | re.DOTALL)
    cleaned = re.sub(r'\s+on\w+\s*=\s*"[^"]*"', "", cleaned,
                     flags=re.IGNORECASE)
    return cleaned

Regex-based HTML sanitization is a well-known anti-pattern. <scr<script>ipt> survives one pass. Single-quoted handlers (onclick='alert(1)') survive. Many vectors (iframe, svg, object, data URIs) are entirely unhandled. Output goes to a Jinja |safe filter — stored XSS class.

  • Single-agent reviewer: empty review. Caught nothing.
  • Independent arbiter (iter2): 5 findings, 3 critical.
  • Mutual triage (iter3): all 3 criticals voted KEEP by both voices → blocking tier.

Full step-by-step in results/pr_009_worked_example.md.

Methodology notes

  • Eval-first. No prompt change without rerunning the full 20-PR corpus.
  • Critical recall reported separately. Weighted-average score would have hidden the iter1 arbiter dropping criticals to gain medium-tier precision.
  • Per-stage capture. Runner saves reviewer-only and arbiter-only finding lists per PR. Inspecting the divergence is what revealed both multi-agent value and the iter4 corpus mislabel.
  • Cache-reuse across iterations. Iter2 reviewer findings get reused as iter3 input — no re-running the upstream agent when only the downstream change matters.
